# Markup App — Architecture Guide

## Goal
A dictionary entry editor for the Belarusian–Russian dictionary. Headword-only search, fixed QHBoxLayout (no splitter) with an entry list and a dual-mode editor (Text = raw XML, Author = rendered WYSIWYG). Saves changes back to the source XML files in `dictionary_app/data/dictionary/`.

## Project Layout
```

└── markup_app/                 # markup app - DELETE markup_app/ to remove it
    ├── __init__.py             # exports MarkupMainWindow (from .main_window)
    ├── main_window.py          # main window, search, entry list, toolbar buttons/context menus, save logic, checked-tracking delegate, broken-links analyzer wiring

    │   ├── checked_state.py    # per-entry checked state, persisted to services/build/markup_checked.json
```

**Deletable as a unit.** `markup_app/` sits beside `dictionary_app/` and imports shared code from it, but nothing in `dictionary_app/` imports `markup_app/`. To remove the markup app, delete `markup_app/` - the dictionary app keeps working. For future changes: never add markup-only files or symbols to the shared `dictionary_app/` modules (`theme/`, `utils/`, `localization/`, `format/`, `db/`, window code); keep every markup-app-specific thing inside `markup_app/`, mirrored under the matching subpackage (localization strings → `markup_app/localization/strings.json`, colors/metrics/stylesheets → `markup_app/theme/*`, glyphs → `markup_app/utils/constants.py`, non-UI logic → `markup_app/services/`, editor pane → `markup_app/panels/`, runtime artifacts → `markup_app/services/build/`).

The launcher (`markup_app/run.py`) inserts the project root on `sys.path`, constructs `QApplication` first, then `MarkupMainWindow(create_search_engine())`. `get_source_path` is imported from `dictionary_app.db.build_database` (never re-derive paths).

## Key Design Decisions

### Window Layout (`MarkupMainWindow.setup_ui`)
- Fixed `QHBoxLayout` (no splitter): entry list at stretch 0 + editor at stretch 1
- Window default size: 765x650 px
- Top row (`top_layout`, spacing `TOP_LAYOUT_SPACING`): `SearchBox` (stretch 1) + ґ-insert button + duplicates toggle + broken-links toggle + rebuild button (all `BUTTON_SIZE`=30x30). The checked toggle and Save button are NOT here — they live in the entry-window overlay (see Toolbar Buttons)
- Entry list: `QListWidget`, `NoFocus`, fixed width `RESULTS_MIN_WIDTH`=150px, horizontal scrollbar off
- Editor container min width set to `ENTRY_MIN_WIDTH`=300px
- Global stylesheet applied via `QApplication.instance().setStyleSheet(MARKUP_GLOBAL_STYLE)`

### Toolbar Buttons (`MarkupMainWindow.setup_ui`)
- **Duplicates toggle** (`_duplicates_toggle`): checkable, `DUPLICATES_MARKER` (👯), tooltip `app_buttons.duplicates.tooltip` ("Загалоўкі-блізьнюкі"); when ON, `_duplicate_filter` narrows the result list to unresolved duplicate groups (`_is_resolved_duplicates`). `_update_duplicates_pressed` mirrors the check state into the `pressed` property.
- **Duplicate resolution (`_duplicate_filter` / `_is_resolved_duplicates` / `_all_ids_resolved`):** rows are grouped by de-accented headword (`remove_accents(headword)`); a group of ≥2 is shown only when it is UNRESOLVED. A group is resolved (hidden) when every member row maps to a distinct entry/`hw_xml_id` identity — each dictionary row contributes its `entry_link` + `hw_xml_id`, each sub-headword row its `entry_link` plus the `hw_xml_id`s matching its `(main_entry_id, headword, link)`, and `_all_ids_resolved` requires every row to have at least one id and no id to repeat across the group. So genuinely distinct homonym entries are hidden, while rows that collide without distinct IDs stay listed.
- **Same-entry duplicate collapse (NORMAL list only):** when NO filter is active (`_duplicates_toggle` off AND `_broken_mode is None`), `_display_results` collapses rows that share a DB entry id + accent-stripped headword to a single row via `dictionary_app.utils.text_utils.collapse_same_entry_duplicates` (first occurrence wins) — e.g. `зачапіцца` (entry 88 listed twice) shows once; genuine homonyms in different entries stay separate. When EITHER filter is active the collapse is skipped and the raw rows are shown, so the 👯 groups/⛓️‍💥 flags can be inspected per row. Clicking the collapsed row passes `occurrence=0` → the first matching `<hw>` is marked/scrolled-to (the `_target_hw` occurrence logic only distinguishes rows when the filters expose both).
- **Broken-links toggle** (`_broken_links_toggle`): checkable, `BROKEN_LINKS_MARKER` (⛓️‍💥), tooltip `app_buttons.broken_links.tooltip` ("Парушоныя залежнасьці"); right-click opens `_broken_menu` — three options from `app_buttons.broken_links.dropdown.*`: `missing_links`, `unresolved_links`, and `ambiguous_grammar`, built as `_BrokenCheckOption(text)` rows mirroring the settings-menu `_CheckOption` look & logic (CHECK_MARK/CHECK_BLANK glyph + label, min-height `SEARCH_BOX_HEIGHT`, `MENU_OPTION_MARGINS`, `COLOR_DISABLED_FG` on the sole disabled one): each is an independent check toggle, at least one must stay checked (`_sync_broken_option_active` disables the only-checked option), clicking keeps the menu OPEN and re-filters live (`_on_broken_category_toggled`); all three checked = `'union'`, a subset = that category set. While the filter is OFF (`_broken_mode is None`) `_sync_broken_options` defaults every box to CHECKED (the union) — so startup and right-click both show all-three checked; an ACTIVE subset mirrors exactly on reopen. Left-clicking the toggle sets full union (all boxes checked); clicking it again clears the filter (`_apply_broken_mode(None)`). The label carries NO count suffix. Right-clicking (opening the menu) sets the button's `pressed` property to `menu` (`_sync_broken_options` mirrors the current mode into the boxes first), which `MENU_BUTTON_STYLE` renders as the clicked rim/background (`COLOR_SELECTED_BG` + `COLOR_BORDER_SELECTED`, `COLOR_MENU_PRESSED_FG`).
- **Rebuild button**: `RELOAD_MARKER` (🔄), tooltip `app_buttons.rebuild_database.tooltip`, runs `_on_rebuild`.
- **Insert-ґ button** (`_insert_letter_g_button`): shared `InsertLetterGButton` placed between the search box and the duplicates toggle (see AGENTS.md → Insert Letter G Button). `_insert_letter_g` inserts `INSERT_LETTER_G` (`ґ`) at the caret of the focused `SearchBox` — focusing the main search box first when none is focused.
- **Checked toggle** (`_checked_toggle`) — now lives in the ENTRY WINDOW (`EditorPane` top-right floating overlay via a `QGridLayout`, NOT the top toolbar): plain button (no rim/background, `ENTRY_CHECKED_TOGGLE_STYLE`), checkable, showing CHECK_BLANK/CHECK_MARK. Left-click toggles the current entry's checked status (`_on_checked_toggle`); tooltip is state-correct (`entry_status.checked.tooltip` when checked, `entry_status.unchecked.tooltip` when not). Right-click opens `_checked_menu` — one command option (`editor.entry_status.dropdown.uncheck_all`) wired to `_on_uncheck_all` (closes the menu, unchecks everything); its dropdown anchors at the button's label baseline so it opens adjacent to the glyph (not at the 30px box bottom). Shown on entry load (`_load_result`); `MarkupEditor.checked_toggle` is the `EditorPane.checked_toggle` alias. **Scrollbar-aware (preserve):** the overlay grid has the tabs spanning two columns, with column 1 as a spacer; `_update_overlay_inset` sets that column's minimum width to `overlay_right_inset(entry_wrapper, current_widget)` (see Scroll Bar Utility in `AGENTS.md`) on both edits' `verticalScrollBar().rangeChanged` and on `_on_tab_changed`, so the overlay clears the active tab's scrollbar and sits flush right otherwise. The overlay widget is a `QHBoxLayout` holding the checked toggle and the Save button (left→right).
- **Save button** (`_save_button`, 💾 `FLOPPY_MARKER`) — migrated into the SAME entry-window overlay, immediately to the RIGHT of the checked toggle (`EditorPane.save_button` / `MarkupEditor.save_button`; `MarkupWindow._save_button` is the alias), borderless via `ENTRY_CHECKED_TOGGLE_STYLE`, tooltip `editor.save.tooltip` ("Захаваць зьмены"). Hidden until the entry is modified; `_on_content_changed` shows it and `_save_current` / entry load (`_load_result`) hide it; left-click calls `_on_save` → `_save_current`. Ctrl+S still saves. NOT in the top toolbar.
- **Shared context-menu pattern (preserve):** `QMenu` + `QWidgetAction.setDefaultWidget(_MenuCommandOption(...))`; opening (`_on_*_menu_requested`) sets the button's `pressed` property to `'menu'` (unpolish/polish) and pops at `mapToGlobal(QPoint(0, anchor))` (`anchor` = `_open_button_menu`'s optional 3rd arg, default `button.height()`; the checked toggle passes its label baseline); `aboutToHide` → `_on_*_menu_closed` sets `*_consume = btn_rect.contains(QCursor.pos())` and calls `_update_*_pressed` (back to `'true'`/`'false'`); the button's `eventFilter` branch swallows the NEXT `MouseButtonPress` while the consume flag is set, so the click that dismissed the menu does not toggle the button. `_MenuCommandOption.mousePressEvent` accepts the event (menu stays open) and calls its callback (`None` = no-op).

### Entry List
- Headword-only search (`search_in_headwords=True`)
- Fixed width (`RESULTS_MIN_WIDTH` = 150px), horizontal scrollbar off
- `ElidingDelegate` from `dictionary_app/widgets/result_list_helpers.py` elides text exceeding viewport width; `select_row`/`navigate_rows`/`clamped_row` from the same module handle selection and keyboard navigation
- `_BorderDelegate` subclasses `ElidingDelegate` and owns all visual state: custom background + left-border color per state, driven by `_checked_state.is_checked(...)` + hover + selection
- Hover tracking via `eventFilter` on the viewport (MouseMove + Leave events); `_hovered_row` on the delegate drives the hover paint, `Leave` resets it
- Items carry `UserRole` = entry_link, `UserRole+1` = headword, `UserRole+2` = entry_id, `UserRole+3` = source_file
- First result row auto-selected after `_display_results`
- Keyboard nav: search box Up/Down signals route to `navigate_rows`; Enter triggers `_on_activate` → simulated click

### Checked State
- Per-item key = `"{source_file}:{entry_link}:{headword}"` — keyed on source file + entry XML ID (not just entry_id) so collided/deduped headwords and sub-headwords stay independent
- Persisted to `markup_app/services/build/markup_checked.json` via `CheckedState`
- `CheckedState.save()` called on every toggle (real-time persistence); writes UTF-8 with `ensure_ascii=False` (keeps Cyrillic) and `indent=2`, creating `markup_app/services/build/` via `os.makedirs(exist_ok=True)` if missing.
- `CheckedState._load()` is resilient: an empty state file loads as `{}`; a corrupt (JSON-decode-failing) file is backed up to `{path}.bak` and the state resets to `{}` instead of crashing the app.
- API: `is_checked(source_file, entry_link, headword)`, `toggle(...)` (returns the new state and persists), `save()`, `migrate(conn)`
- `migrate(conn)` runs at startup and rewrites legacy-format keys (e.g. old `{entry_id}:{headword}`) to the current key schema
- Visual states via `_BorderDelegate.paint()`, with the shared palette (`COLOR_NORMAL_BG`/`COLOR_HOVER_BG`/`COLOR_SELECTED_BG`/`COLOR_BORDER_DEFAULT`/`COLOR_BORDER_SELECTED` from `dictionary_app/theme/widget_styles.py`) plus local checked-state colors (from `markup_app/theme/widget_styles.py`):
  - Non-checked idle: white bg, no border
  - Non-checked hover: `#fafafa` bg, grey border
  - Non-checked selected: `#edf7fd` bg, blue border
  - Checked idle: `#c8f7c5` bg, green border
  - Checked hover: `#b8f0b5` bg, green border
  - Checked selected: `#7cbf7a` bg, green border
- Text always painted black (palette override: `QPalette.Text` + `QPalette.HighlightedText` = black)
- Checked toggle button glyphs come from `dictionary_app/utils/constants.py`: `CHECK_BLANK` (⬜) when unchecked, `CHECK_MARK` (✅) when checked; the Save button uses `FLOPPY_MARKER` (💾), the duplicates toggle `DUPLICATES_MARKER` (👯), the broken-links toggle `BROKEN_LINKS_MARKER` (⛓️‍💥), the rebuild button `RELOAD_MARKER` (🔄) — the last four from `markup_app/utils/constants.py`. Never re-type the emoji in this file.
- Entry list has no `item:hover`/`item:selected` CSS rules -- the delegate handles all visual states

### Editor
- `QTabWidget` with two panes: **Text** (editable `QTextEdit`) and **Author** (read-only `QTextEdit`)
- Author pane uses `ENTRY_STYLESHEET` from `dictionary_app/theme/widget_styles.py` via `document().setDefaultStyleSheet()`
- Author pane re-renders on tab switch
- `EditorPane._is_modified` tracks changes; `content_changed` signal emitted on text change
- `set_entry()` blocks signals during `setPlainText()` to avoid false dirty state; also resets `_text_edit._pending_tag_delete = False` and clears extra selections so stale highlight/deletion state never carries over between entries
- **Plain-text paste enforced:** `setAcceptRichText(False)` + `canInsertFromMimeData` (text only) + `insertFromMimeData` → pasted HTML/rich content is inserted as plain text via `insertPlainText`, never as rich text (prevents hidden format junk inside the XML)
- Author pane render: `_render_author` tries `ElementTree.fromstring` + `format_entry`; on `ParseError` it falls back to showing the raw XML as plain text (so the author tab doesn't crash on a transiently invalid entry)
- **Sub-headword mark / d-span underline:** clicking a sub-headword row calls `mark_sub_hw(headword, occurrence)` — it moves the caret to the Nth `<hw>` matching the headword (normalized), scrolls the line containing it to the TOP of the editor viewport (`_scroll_line_to_top`, clamped like the dictionary app's `scrollToAnchor`), and draws an orange bottom-underline (`COLOR_D_SPAN_UNDERLINE` = `#c2571a` from `markup_app/theme/widget_styles.py`, `_compute_d_span_underline`) across the innermost `<d>` span containing it; a `<hw>` outside any `<d>` underlines the whole entry UNLESS the non-d region holds ≥2 `<hw>`s (then no underline — the region is ambiguous). Clicking a MAIN (non-sub-headword) row calls `mark_main_non_d(headword, occurrence)`: when the entry contains at least one `<d>`, it underlines the non-`<d>` region(s) — the entry span minus every `<d>` span (`_non_d_regions`, one segment per gap, so an entry like `main…<d>…</d><d>…</d>…` underlines the head and tail but never a `<d>`); when the entry has NO `<d>` it draws nothing and clears `_target_hw` (so the whole-entry fallback can't fire). Both marks share `_target_hw`; `mark_sub_hw` clears `_non_d_underline` and vice-versa, and `_compute_d_span_underline` is suppressed while `_non_d_underline` is non-empty. Same-entry duplicate rows differ by `occurrence`: `on_result_clicked` counts the clicked row's index among rows with the same `(entry_id, headword, entry_link)` triple and passes it to `_load_result`, and the "already current" guard compares `current_occurrence` too — so clicking row 0 vs row 1 of an entry listed twice underlines DIFFERENT d-spans.

### Link markers & dependency tooltip
- **Dependency marker:** each `<entry>` and `<hw>` opening tag that is TARGETED by a resolved `<see>` (or a local `<g hw=…>`) gets a 🔗 marker drawn on its opening `<` in the Text pane — `LINK_MARKER = '\U0001F517'`, `_LINK_MARK_COLOR = QColor(70, 130, 180)`, emoji font Segoe UI Emoji.
- **Reserved space, no real chars:** the gap is carved with a `QTextCharFormat` letter-spacing on the `<` char alone (`setFontLetterSpacingType(QFont.AbsoluteSpacing)` + `setFontLetterSpacing(emoji_width + 2)`) applied by `_apply_link_gaps()` under `blockSignals(True)`, followed by `document.clearUndoRedoStacks()` (plural `Stacks`). `toPlainText()` is unchanged, so save/scan/copy/char-offsets all stay intact — never insert a real character (it would break `_scan_tags`/`<(\w+)`).
- **Lazy:** offsets+tooltips are computed ONCE per load (`_load_result` → `_refresh_link_marks()` → `EditorPane.set_link_marks(offsets, tooltips)`); there is NO debounce/live update. `mergeCharFormat` DOES create an undo command and `setUndoRedoEnabled(False)`+re-enable wipes the whole undo stack, so live updating would either record undo entries or destroy history — hence load-time only.
- **Target set** (`MarkdownMainWindow._link_marker_data(text)` → `(offsets, tooltips)`): marks `<entry>` when a resolved `<see>` row's `row[0]` equals the current entry id; marks `<hw>` when its `id` (row[3]) or normalized headword (row[1]) matches, or a local `<g hw=…>` targets it. Unresolved `<see>`s and `<g>`-only targets add no marker/tooltip line.
- **Tooltip (rich text, 400 ms hover):** `_TagAwareTextEdit` sets `setMouseTracking(True)`; `_link_symbol_box(start)` is shared by `paintEvent` and the hover hit-test `_link_mark_at(point)`; `mouseMoveEvent`/`leaveEvent` arm/clear a single-shot `_link_tooltip_timer` that calls `_show_pending_link_tooltip` → `QToolTip.showText`.
  - Line 1 (title, localized): `strings.editor.link_dependencies.entry.tooltip` ("Пакліканьні на гэты артыкул:") for `<entry>` markers, `strings.editor.link_dependencies.headword.tooltip` ("Пакліканьні на гэты загаловак:") for `<hw>` markers.
  - Each dependency line = `&bull; ` + `<b>owning-hw(s)</b>` + `": "` + the raw `<see …>…</see>` span, all `html.escape()`d (so `<see>` is never parsed as HTML). Lines joined with `<br>`.
  - **Owning hws:** `BrokenLinkAnalyzer.owning_hw_texts(block, see_start)` buckets elements by nearest `<d>` (via `_collect_regions`), returns the bucket's `<hw>` texts excluding `excl` (regex fallback if the block won't parse). Displayed RAW (accents/ё preserved, exactly like the entry list) and joined with `', '` — do NOT `normalize_headword` them (normalization is only for matching).
  - **Width:** `_widen_tooltip_html(text)` wraps the lines in `<table width="{1.5×widest_line + 8}">` (widest measured with `QFontMetricsF(self.font())` after stripping tags/unescaping) to make the box 50% wider than the longest line.
- Markers+tooltips are reset in `EditorPane.set_entry` and `clear` (`_link_marks = []`, `_link_mark_tooltips = {}`). A `<hw>`/`<entry>` targeted only by `<g hw=…>` still gets the 🔗 marker but no tooltip (the tooltip dict has no entry for it).

### Attribute Completion (Content-Completion Assistant)
- Oxygen-style live prompt: typing a SPACE right after an opening tag's name pops a dropdown of the attributes that tag supports. The list filters on every keystroke; Up/Down move the selection, Enter/Tab (or a mouse click) inserts, Esc closes.
- **Spec source of truth:** `dictionary_app/utils/xml_schema.py` — a single shared registry imported by BOTH the completion prompt and the app's attribute reads (entry/highlight formatters, `dictionary_app/utils/content_rules`, markup broken-links, DB build/search, markup source cache). It defines `ATTRIBUTES` (tag → ordered `(name, kind)`; `kind` = `TEXT`/`BOOL`), the `ATTR_*` name constants (`ATTR_ID`/`ATTR_HW`/`ATTR_ENTRY`/`ATTR_EXCL`/`ATTR_N`/`ATTR_LANG`/`ATTR_CODE`/`ATTR_SYN`), and helpers `attribute_names(tag)` / `is_boolean(tag, name)` / `unknown_attributes(root)`. Currently `entry:id`, `hw:id,excl`, `g:hw`, `see:entry,hw,syn`, `sense:n`, `i:lang,excl`, `lang:code`. Add an attribute HERE (and to `MARKUP_PATTERNS.md` / `markup_attributes.xlsx`) and it appears in the prompt and everywhere the reads are wired. `<sense>` has NO `hw` attr (support removed — see AGENTS.md). `sources.xml` (`section/@id`) is a separate document shape and is intentionally NOT in this registry.
- **Context parser** (`detect_context(text, pos)`) scans back from the caret to the nearest `<` with no `>` in between, reads the tag name, and tokenizes the attribute region: it returns `CompletionContext(tag, present, fragment)` only when the caret is in the attribute-NAME slot; it returns `None` inside a quoted/unquoted value, in tag content, on a closed tag, on a partial tag name (no trailing space yet), and for tags with no spec. `present` (already-typed attrs) is excluded from the candidates; matching is prefix, case-insensitive.
- **Insertion:** a TEXT attr inserts `name=""` and places the caret between the quotes; a BOOL attr inserts `name="true"` at once (caret after). The typed `fragment` is replaced. Wrapped in `beginEditBlock`/`endEditBlock` so one undo removes the whole insertion.
- **Popup** (`AttributePopup(QListWidget)`, parented to the edit): `Qt.Tool | FramelessWindowHint | WindowStaysOnTopHint | WindowDoesNotAcceptFocus` + `WA_ShowWithoutActivating` + `NoFocus`, so the editor keeps keyboard focus (keys are handled in `_TagAwareTextEdit.keyPressEvent` via `_handle_completion_key`) while mouse clicks on a row still fire `itemClicked`. Positioned under the caret (`cursorRect` → `mapToGlobal`) and flipped above when it would overflow the screen; width fits the longest item, height capped at `MAX_VISIBLE`=8 rows. Styled by `ATTRIBUTE_POPUP_STYLE` (`markup_app/theme/styles.py`) using the shared palette — `COLOR_NORMAL_BG` bg, `COLOR_BORDER_DEFAULT` border + 5px radius, hover = `COLOR_HOVER_BG` + `COLOR_BORDER_DEFAULT` left accent, selected = `COLOR_SELECTED_BG` + `COLOR_BORDER_SELECTED` left accent (mirrors `RESULTS_LIST_STYLE`); item text is ALWAYS black — `color: black` on `::item`/`:hover`/`:selected`/`:selected:!active` PLUS a `QPalette.Text`+`HighlightedText`=black override, so the selected row stays black while focused exactly like the entry list (never `COLOR_MENU_PRESSED_FG` here); `FONT_STACK`/12pt, bold inherited from the global `QListWidget` rule. No hard-coded colors.
- **Trigger/retrigger:** only a typed SPACE (or a text-changing key while open) calls `_refresh_completion`; the popup does NOT reappear merely on caret re-entry (arrow keys hide it). It also hides on `mousePressEvent`, `focusOutEvent`, on `textChanged` (external edits), after accepting an item, on Esc, and whenever the parser returns no context/candidates.

### Tag Buttons
- Three groups (`TAG_BUTTON_GROUPS` in editor.py): [`d, hw, n, g, sense, t, ex, st, src, see, lang`] + [`br`] + [`p, i, b`] (the `tp` and `lvl="1"` buttons were removed — the APP no longer processes that markup, see AGENTS.md → Source Data State)
- One `QHBoxLayout`: `EDITOR_TOOLBAR_SPACING`=2 between buttons, `TAG_BUTTON_GROUP_GAPS` = [`EDITOR_TOOLBAR_GAP`=15, `EDITOR_TOOLBAR_GAP_LARGE`=15] between the groups, trailing `addStretch()` — built in the layout loop in `editor.py` (all `EDITOR_TOOLBAR_*` from `markup_app/theme/layout_constants.py`).
- **Gap ceiling (preserve):** 15px is the MAXIMUM group gap that fits the default window: editor content ≈615px (765 − 150 results − layout margins) vs ≈540px of buttons + 10px margins + ≈34px of item spacing → only ~31px of headroom across both gaps. Raising either constant overflows/clips the row at the default width; wider windows donate the extra space to the trailing stretch, never to the gaps.
- Auto-sized to fit content (no fixed width)
- Wrapping: wrap selected text in `<tag>…</tag>`, or insert empty `<tag></tag>` with cursor between; `insert_tag` special-cases `br` → `<br />`, `sense` → `<sense n="">`, `lang` → `<lang code="">` (no selection: caret placed between the quotes; selection: wrapped)
- Style: `TAG_BUTTON_STYLE` (transparent bg, no border, padding 2px 6px)

### Backspace/Delete Logic (`_TagAwareTextEdit.keyPressEvent`)
1. **Inside a tag** (`_is_inside_tag`): normal character deletion (both keys), EXCEPT when the deleted char is inside the tag NAME and the tag has a structural partner → mirrored rename (see Tag Name Renaming below)
2. **At a tag boundary** (`_pair_at_deletion_boundary`): the pair is highlighted (yellow, `COLOR_HIGHLIGHT_BG` from `dictionary_app/theme/widget_styles.py`) and pending; the second press of the same operation removes both tags, keeping inner content. Highlight triggers ONLY when the character about to be deleted is a tag delimiter of the open/close pair:
   - **Backspace** next to the `>` of the opening tag (cursor right after `<t>`) or the `>` of the closing tag (cursor right after `</t>`)
   - **Delete** next to the `<` of the opening tag (cursor right before `<t>`) or the `<` of the closing tag (cursor right before `</t>`)
   - Cursor inside pair content (e.g. `<t>сорт{cursor}</t>` + Backspace) → **normal deletion** of the word char (deletes "т"), never the tags
3. **Selection matching `<tag>…</tag>` pattern** (`_PAIR_SELECT_RE`, Backspace only): removes both tags, keeps content, cursor after last word
4. **Any other Backspace/Delete**: normal deletion; clears pending state and extra selections (also any non-Backspace/Delete key)
- `_is_inside_tag()` checks if pos is between `<` and `>` of any tag
- `_pair_at_deletion_boundary()` maps the char about to be deleted (pos-1 for Backspace, pos for Delete) to a tag delimiter; if that char is not a `<`/`>` it returns `(None, None)` (normal deletion)
- `_find_tag_pair_at_boundary()` finds the pair owning that delimiter via stack-based parsing: it pops open/close matches and returns the pair only if the char is that pair's open-start, open-`>`, close-`<`, or close-`>`. This is boundary-based (NOT position-in-range), so at a shared boundary like `<d><hw>…` a Backspace on the `>` resolves to `<d>` and a Delete on the `<` resolves to `<hw>`. It is fully generic by tag NAME (any tag, including `entry` and future tags, works); there is NO hard-coded tag exclusion. Self-closing tags (e.g. `<br />`) are treated as their own "pair" — the whole tag is highlighted/deleted at its `<`/`>` boundary, so Backspace right after `<br />` removes the tag instead of corrupting the markup. The deletion path handles the self-closing case (`open_tag is close_tag`) as a single removal; otherwise close-then-open removal order.
- State tracked via `_pending_tag_delete`, `_pending_open_tag`, `_pending_close_tag`
- **Direction guard:** the pending state records which key armed it (`_pending_delete_forward`). The second press only deletes if the SAME key is pressed again (matching direction). If the OPPOSITE key (Backspace↔Delete) is pressed, the pending state is reset and the new key's boundary detection runs instead (e.g. at `<d>|<hw>`: Backspace highlights `<d>`, then Delete re-detects and highlights `<hw>`, then Backspace re-detects `<d>` again — no deletion until the same key repeats).
- **Any cursor movement** (arrow keys, mouse click, etc.) resets the pending state and clears the highlight via a `cursorPositionChanged` handler (`_reset_pending_tag_delete`) — so the pending pair deletion is only valid if the cursor was NOT moved after the first Backspace/Delete press. (The batch-delete flow runs under `blockSignals(True)`, so its internal cursor moves don't trip the reset.)
- **Deletion mechanics (preserve):** when deleting a pending pair, the CLOSE tag is removed FIRST, then the OPEN tag (removing close-then-open avoids shifting the other tag's char offsets). The two removals are wrapped in `cursor.beginEditBlock()`/`endEditBlock()`, so a single Ctrl+Z undoes BOTH tags (not one at a time). Signals are blocked during the batch edit, then `textChanged` is emitted manually so the save button appears.
- **Undo restores, highlights, AND re-arms the deletion:** at deletion time the pre-deletion text is snapshotted (`_pair_delete_snapshot`) along with the removed tag spans and the key direction (`_last_deleted_forward`). A `textChanged` handler compares the document against the snapshot; when it matches (i.e. the pair-delete macro was undone), it re-arms the full pending state (`_pending_tag_delete`/`_pending_open_tag`/`_pending_close_tag`/`_pending_delete_forward`) and highlights both tags — so ONE next press of the same Backspace/Delete key deletes the pair again (Ctrl+Z + 1 press, not Ctrl+Z + 2). The highlight/re-arm is applied deferred via `QTimer.singleShot(0, …)` (re-checking the text still matches) because Qt emits a trailing `cursorPositionChanged` after `textChanged` during undo that would otherwise wipe the state synchronously. Direction guard still applies after undo: pressing the OPPOSITE key resets and re-detects. Snapshot is cleared once matched, reset in `set_entry()`, and overwritten by each new pair-deletion; typing between delete and undo does NOT trigger it (undo of the typing produces non-matching text).

### Tag Name Renaming (`_TagAwareTextEdit` open↔close mirroring)

Editing characters inside a tag's NAME updates the structurally paired partner tag on every keystroke (live, per keystroke):

- **What triggers it:** a name character (ASCII letters/digits/`_`) is inserted, deleted (Backspace/Delete), or replaces a selection lying entirely within the tag NAME region (between `<`/`</` and the first non-name char). Edits to attributes, to `<`/`>` delimiters, or outside tags never mirror; the insertion point must be inside the name inclusive of its end (so appending at the name end mirrors, but typing a space right after the name does not).
- **Partner resolution:** structural stack pairing — `_scan_tags()` scans `<…>` spans (tolerating EMPTY names so the `<></>` transient works; `</>` is a closing tag, NOT self-closing) and `_partner_tag()` matches open/close by name like `_find_tag_pair_at_boundary`, so nested same-name tags (`<t><t>…</t></t>`) resolve deterministically (inner↔inner, outer↔outer). Self-closing tags (`<br />`) and tags with no structural partner are never mirrored (normal typing/deletion applies).
- **Empty-name transient:** deleting a name down to `<></>` and retyping keeps mirroring (both sides are tracked while empty), so a full rename (Backspace-to-empty + retype) stays in sync at every step.
- **One undo step:** the typed change and its partner mirror run inside a single `beginEditBlock()`/`endEditBlock()` block (`_apply_synced_name`), so ONE Ctrl+Z reverts BOTH tags.
- **Caret stays at the typed location:** the mirror edit never moves the caret to the partner; the caret shifts only if the partner's mirror edit sits before it in the document (partner index offset is computed from the main edit's net length change, incl. the adjacent-pair case where the closing tag starts exactly at the opening tag's `end`).
- **Not hijacked:** Ctrl/Meta-modified Backspace/Delete (e.g. word delete) and non-name characters fall through to plain `QTextEdit` handling; the pair-delete/selection flows above are unaffected (the sync hooks are the inside-tag delete branch and the plain-insert branch of `keyPressEvent`).

**Resolution of inner/outer tags at any given boundary is deterministic:**
- At a boundary SHARED by an inner and outer tag (e.g. the cursor sits between `<d>` and `<hw>`), the direction decides: Backspace (deleting the `>`) targets the outer tag; Delete (deleting the `<`) targets the inner tag. This is because the rule is "which tag's delimiter char is being deleted."
- At a boundary NOT shared (e.g. cursor before `<g>` inside a `<t>`, or right after `</g>`), the tag at the exact cursor boundary wins, so the inner `<g>` is highlighted/deleted while the outer `<t>` is untouched. Previously this returned the OUTERMOST pair; the boundary-based rewrite now prefers the exact-boundary tag instead.
- Preserve the close-first removal order for open/close pairs (self-closing single removal is the one exception).

### Save Flow
- Save button hidden when no changes; shown on `content_changed`
- `_save_current()`:
  1. Guard: returns immediately if no `current_result` or editor not modified (checked via `editor.pane.is_modified()`).
  2. Validation: parses the new XML with `ElementTree.fromstring`; on `ParseError` shows a warning `QMessageBox` and aborts (does NOT write).
  3. Re-reads the file, splits it into raw `<entry>...</entry>` blocks via regex, and locates the ORIGINAL block by comparing against the raw block text captured at load time (`self._loaded_raw[entry_id]`, from `on_result_clicked`). Saving requires the block to match **exactly once** — if it is missing or ambiguous (duplicate blocks present), it warns and aborts WITHOUT writing. This prevents accidental replacement of a wrong entry (no more `entries[0]` fallback).
  4. `content.replace(block, new_entry_string, 1)` replaces that unique block in place; everything else (blank lines between entries, other entries' original markup such as `<br></br>`) is preserved untouched.
  5. After a successful write: updates `_loaded_raw[entry_id]` to the new block, sets `_has_unsaved = False`, directly sets `editor.pane._is_modified = False` (bypass, since textChanged normally re-marks dirty), hides the save button.
  6. Updates **all** `current_results` entries sharing the same `entry_id` (main + sub-headwords all show the saved version), preserving each row's own headword/link/source_file
- `_read_entry_from_source(entry_id, source_file, headword=None, entry_link=None)`: matches a raw `<entry>` block by **entry XML ID** (`entry_link`, normalized accent- and ё-insensitively and looked up in the `by_link` index) and/or by headword (`_block_matches`, accent- and ё-normalized, case-preserving). Returns `None` if nothing matches or on `ParseError`/`OSError` — it NEVER falls back to the first entry in the file.
- **Ambiguous headword/ID match → block disambiguated by the row's own `full_entry`:** when ID-less lookup yields several candidate blocks (distinct entries that collided on a normalized headword, e.g. `ча́пацца`/`чапа́цца` or two entries sharing the same sub-headword), `_read_entry_from_source` picks the candidate whose whitespace-stripped content equals that `entry_id`'s DB `full_entry` snapshot — never the first block for both rows. A single candidate keeps the old first-match behavior, and if no candidate matches `full_entry` it falls back to the first. This is what makes each row of an unresolved duplicate pair (Show duplicates) load its own article.
- **`entry_link` is the owning entry's own `<hw id>` and holds no `#H` suffix.** The markup app uses the same ID-only scheme as the dictionary app (see AGENTS.md → Cross-Reference IDs): `sub_headwords.link` is the parent entry's ID, and sub-headword identity comes from `headword` plus `hw_xml_id`, never from a compound link. The `_block_sub_links()` helper of the old `E#H` scheme is gone; raw block indexing keys on the entry ID alone.
- `_block_matches(block, target_norm)` compares every `<hw>` text in a block (accent- and ё-normalized, case-preserving) — handles entries with multiple `<hw>` (sub-headwords). Case is preserved because the dictionary keeps case-distinct headwords as separate entries (`Юр` vs `юр` each get their own block). `excl` variants are still matched (an entry is loadable via either its indexed or excluded headword).
- `<hw excl="true">` (an excluded headword variant, see AGENTS.md → `<hw excl="true">`) does NOT become a `dictionary`/`sub_headwords` row, so it never appears in the entry list here either — the entry is listed under its remaining (first non-excl) `<hw>` only.
- Ctrl+S shortcut (`keyPressEvent`)
- Auto-save on entry switch (`on_result_clicked` calls `_save_current` first when `_has_unsaved`) and on `closeEvent`
- `source_file` column in `dictionary.db` tracks which file each entry came from

### Entry Loading
- `on_result_clicked` matches on **both** `entry_id` AND `headword` — sub-headwords share parent's `entry_id` so matching on `entry_id` alone would load the main headword's data instead
- When switching from a dirty entry it auto-saves first; then it re-reads the raw `<entry>` block from the source file and stores it in `self._loaded_raw[entry_id]` (also used as the editor text, so the editor always works from the file's exact markup). If no block is found, it keeps the DB-cached `full_entry`.
- `_loaded_raw` grows one raw block per entry opened in a session and is only popped on source re-read failure — the only unbounded cache in either app, but bounded by the number of entries EDITED per session (negligible at the current corpus; see AGENTS.md → Performance / Scale Notes).
- Checked toggle button updated on entry load; save button hidden on entry load

### Entry List Order
- The list shows search-engine results in `search_engine` order (empty query = full dictionary `UNION ALL` sub_headwords — duplicates are shown as separate rows by design, see AGENTS.md Search Modes — sorted by `dictionary_app.utils.text_utils.alphabet_sort_key` applied to the DB `sort_headword` column — headword text with embedded `<n>` homonym content stripped, so `ґале́ра ІІ` sorts by `ґале́ра`).
- Collation rules (see `alphabet_sort_key`): compares by Belarusian alphabet (ґ after г, before д); combining accents (U+0300/U+0301) are skipped so accented words collate by base letters; apostrophes (`'`/`’`/`ʼ`) are skipped too (`Юр'е` collates as `Юре`); word breaks (space, hyphen) are strong dividers ranked BELOW all letters (hyphen before space), so a multi-word entry groups right after its single headword — `ґаз, ґаз сьвяціць, ґаза, ґазавая ґрана́та, …`; among equal prefixes, shorter words come first (shorter-first); uppercase only tie-breaks AFTER the letter ranks (`юр` before `Юр`).

### Broken Links Analysis & Filtering (`_broken_row_flags`)
- Lazily computed on first use of the broken filter, cached in `self._broken_flags_cache`; invalidated on rebuild (`_refresh_after_rebuild`) and successful save (`_save_current`). Scans every source file in the DB (`_source_blocks()` → raw `<entry>` blocks).
- **Span-level detection** (`_block_span_flags`): partitions a block into regions = each `<d>` span (keyed by its nearest `<d>` ancestor) + the non-d region (`None`); a nested `<d>` gets its own region. Per region it collects its `hw`/`g`/`see` descendants and computes category flags:
  - `missing_links` / `unresolved_links` from each `<see>` via `_classify_see`.
  - `ambiguous_g` when the region has ≥2 `<hw>` AND ≥1 `<g>` AND (exactly one `<g>`, OR ≥2 `<g>` with at least one unresolved — single-g regions always fire, refinements may come later). A `<g>` resolves if its `hw=` attr ID-matches or accent-matches an `<hw>` WITHIN the same entry.
  - Parsing via `ElementTree`; on `ParseError` falls back to `_block_span_flags_regex` (whole block as one region, all gs unresolved).
- **Headword index** (`_headword_rows`) = `dictionary` rows + `sub_headwords` rows (sub on par with main), cached in `self._headword_rows_cache`, invalidated with the flags cache. Matching uses the app's "current rules": `_see_normalized` = `normalize_jo_to_je(remove_accents(...))`, quote-strip `'"\'„“”'`, `<n>`-tail append (`r'^[,\s]*\d'`) mirroring the formatting link-target logic.
- **Sense-tail stripping** (`split_sense_tail`, applied to every see-word at the top of `<see>` classification): removes a trailing Arabic-digit sense list (`r'[,\s]*\d+(?:[,.]\s*\d+)*$'`) and returns the removed numbers, so `<see>абразок 1, 2</see>` is checked as `абразок` with senses `[1, 2]`. Homonym numbers (Roman numerals) are NOT digits and stay on the word — `<see>грыжа ІІ, 1, 2</see>` is checked as `грыжа ІІ` with senses `[1, 2]`; a bare `<see>грыжа <n>ІІ</n></see>` is checked as the FULL headword `грыжа ІІ` (the `<n>` text is glued into the word and never stripped), so it is `missing_links` when only the plain `<hw>грыжа</hw>` exists. Mirrors the formatting link-target logic (`LinkHandler.parse_link_text` keeps the trailing Roman-numeral homonym marker on the word).
- **Reverse sense check** (`_finalize_resolved` + `_row_has_senses`): when the stripped see-word carried a sense list and resolves to a SINGLE row, the referenced entry must actually contain EVERY listed sense number before it counts as resolved. Sense numbers are collected per entry id from the entry's `<sense n="…">` attributes (with inner `<n>1.</n>` text as a fallback) in `_entry_senses_cache`/`_block_sense_attrs` (cached, invalidated with the flags cache). If any referenced sense is absent it is **missing_links** — so the deliberate "partial nowhere" case `<see>юшка, 3</see>` (юшка has senses 1–2 only) is flagged broken. Sees WITHOUT a sense list skip this check entirely.
- **`<see>` classification** (`_classify_see(word, entry_attr, hw_attr)`; attributes and inner text both quote-stripped):
  - EXACTLY ONE index row matching the see-word (normalized) → **resolved** (or **missing_links** when a sense tail was present and the entry lacks any of the referenced senses — see Reverse sense check), regardless of other attributes (unique word short-circuits).
  - ZERO rows → try attributes: `entry=` pins to an entry whose headword accent-matches, then resolves/`missing`/`unresolved` against that entry's own hws; `hw=` resolves via `hw_xml_id` ID match or accent match. Still nothing → **missing_links**.
  - TWO+ rows → try attributes: resolve if an attr narrows to exactly one; `entry=` on multiple entries or `hw=` on multiple rows → **unresolved_links**; otherwise **unresolved_links** (duplicate-lead = unresolved for now; the `зачапіцца two-rows` case is unresolved until same-entry duplicates get resolved).
  - **Accent rule for `entry=`/`hw=` attributes:** an attr CONTAINING accents must equal the headword exactly (case+accents); an UNACCENTED attr matches accent-insensitively (`remove_accents` equality). Underscores are kept literally (`абора_бечевка` is a valid entry ID).
- **Row mapping**: each flagged span is mapped to the rows of its `<hw>`s. A block's entry id is resolved by `_block_entry_ids` → `entry_link`/`<entry id>` (via `by_link`) else main-headword match (via `by_hw`); a block whose headword collides (≥2 candidate entries, e.g. homonyms) keys its flags by `(source_file, None, hw_norm)` so all colliding rows match. `_broken_row_flags()` returns `{(source_file, entry_id_or_None, row_norm): {flags}}` with `row_norm = remove_accents(hw).lower()`.
- **Filtering**: `_broken_filter(results, mode)` matches a row by `(source_file, id, norm)` else `(source_file, None, norm)`; `mode` may be a string (`'union'` or a single category) or an iterable of categories — matched as an intersection against the row's flag SET (`wanted & row_flags`), so a subset filters the union of its categories. `_broken_mode` itself is `None` (off) or a set of category codes (`{missing_links, unresolved_links, ambiguous_g}` = union). Applied in `_display_results` AFTER the duplicates filter, so `duplicates` + broken mode is an INTERSECTION. The toggle left-click sets full union / clears; the menu checkboxes toggle category membership (menu stays open, live re-filter).
- **Row-click highlight** (`BrokenLinkAnalyzer.spans` → `EditorPane.highlight_broken_links`): when an entry is loaded while `_broken_mode` includes `missing_links`/`unresolved_links`, every matching `<see>` element in that entry is highlighted with `COLOR_HIGHLIGHT_BG` (no delete behavior). When the mode includes `ambiguous_g`, `BrokenLinkAnalyzer.ambiguous_spans(text)` returns the element spans of the region's `<g>`s and `<hw>`s, highlighted with the distinct `COLOR_AMBIGUOUS_G_BG` (peach) / `COLOR_AMBIGUOUS_HW_BG` (lavender) via `EditorPane.highlight_grammar_marks` — so a single entry can show see-links and grammar marks at once. Recomputed by `_refresh_broken_highlight` on load and on mode change (`_see_span_mode` maps the active set to the see-link mode string); the highlights are stored span lists on `_TagAwareTextEdit` (`_broken_link_spans`/`_grammar_g_spans`/`_grammar_hw_spans`), so they SURVIVE cursor moves and are only cleared by loading another entry or leaving those modes (never by clicking elsewhere in the entry). `_element_spans` pairs `<g>`/`<hw>` elements (document order) to opening-tag offsets in the raw text; on `ParseError` a regex fallback flags the whole block.
